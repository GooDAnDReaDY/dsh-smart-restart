# DESIGN — dsh-smart-restart

## 1. Задача

Перезапуск харнесса перестаёт быть операцией «на честном слове»: агент просит перезапуск, а плагин
после старта **проверяет**, что всё поднялось, **сообщает** вердикт в ту сессию, которая просила, и
возвращает **намерение** «что продолжить».

## 2. Границы

**Входит:** перезапуск без привилегий (kill + `Restart=always`), health-check после старта,
отчёт в сессию, файл-намерение, защита от петли, карточка настроек.

**Не входит:** управление другими сервисами, sudo/polkit-настройка, canary-инстансы, автопочинка
чужих плагинов; перезапуск при потере питания; Windows-специфика.

## 3. Пользовательские сценарии

| # | Сценарий | Что видит владелец/агент |
|---|---|---|
| 1 | Агент меняет конфигурацию и просит перезапуск | Инструмент возвращает квитанцию, процесс завершается, systemd поднимает сервис |
| 2 | Проверка после старта | В сессию приходит отчёт: время старта, простой, вердикт по пунктам, «продолжи: …» |
| 3 | Что-то не поднялось | Вердикт `degraded` со списком провалившихся проверок, а не молчание |
| 4 | Перезапуск по кругу | Четвёртый перезапуск за 10 минут отклоняется с объяснением |

## 4. Поверхности

- **Инструменты** `dsh_restart` и `dsh_restart_status`.
- **Карточка настроек** в списке плагинов (`plugins.item` + `settings.plugin.item`).
- **Сообщение в сессию** — основной пользовательский результат: отчёт после перезапуска.

## 5. Контракт инструментов

- `dsh_restart` требует `confirm: true`; принимает `reason`, `resume`, `delayMs`; возвращает
  `{ ok, restarting, delayMs, mode, boot }` либо отказ с причиной (петля, нет юнита, выключено).
- `dsh_restart_status` — только чтение: `{ lastBoot, downtimeMs, restartsInWindow, pendingIntent,
  lastReport }`.
- Значение результата обязано переживать JSON без потерь (никаких `undefined`).

## 6. Состояния

`ok` — все проверки прошли; `degraded` — часть проверок провалилась (список в отчёте);
`disabled` — плагин выключен настройкой; `no-unit` — юнит не найден; `loop-guard` — отказ по
счётчику; `stale-intent` — намерение старше TTL, в отчёт попадает с пометкой.

## 7. Данные и безопасность

- Состояние: `$DSH_HOME/.restart-guard/{marker.json,intent.json,last-report.json,history.log}`;
  намерение содержит id сессии, причину и текст «что продолжить» — секретов там быть не должно.
- Перезапуск по умолчанию не требует прав; режим `systemctl` используется только там, где права
  уже выданы.
- Отчёт не содержит путей, адресов и идентификаторов инфраструктуры за пределами юнита и порта.

## 8. Приёмка

| Проверка | Критерий |
|---|---|
| Тесты | `npm test` без сети и харнесса, зелёный |
| Preflight | без FAIL |
| Тестовый сервер | установка, перезапуск, отчёт в сессию, cleanup |
| Прод | тот же `.tgz`, затем registry-версия; отчёт после перезапуска |
| Интерфейс | карточка: заголовок, раскрытие, сохранение; en + zh |
